# ডেটাবেস Functions 

এই ফাইলে 2টি ফাংশন সাধারণ ও চলতি বাংলায় বুঝিয়ে দেওয়া হলো:

1. **`sp_get_all_owners_details()`** – সব Owner ও তাদের দোকানের বিবরণ একসাথে দেখার ফাংশন।
2. **`fn_refresh_dashboard_stats()`** – ডেটা পরিবর্তন হলে ড্যাশবোর্ডের সব সংখ্যা নিজে থেকে আপডেট করার ট্রিগার ফাংশন।

---

# 1. `sp_get_all_owners_details()`

## সহজ কথায় এর কাজ কী?
Queueless অ্যাপ্লিকেশনের অ্যাডমিন ড্যাশবোর্ডে সব দোকান মালিকদের (Owner) নাম, ছবি, ইমেইল, ফোন, **ঠিকানা (Address)**, দোকানের সংখ্যা এবং দোকানের নামগুলো একসাথে সুন্দরভাবে দেখানোর জন্য এই ফাংশন তৈরি করা হয়েছে।

এটি `owners`, `users`, এবং `shops`—এই 3টি টেবিল থেকে তথ্য এনে একসাথে একটি লিস্ট বানিয়ে দেয়। ফলে প্রতিটা তথ্যের জন্য বারবার আলাদা কুয়েরি চালানোর কোনো দরকার নেই।

---

## ফাংশন চালানোর নিয়ম (Calling Query)
> **মনে রাখুন:** এটি কোনো প্রসিডিউর নয়, এটি একটি **Function**। তাই `CALL` নয়, `SELECT` দিয়ে চালাতে হবে।

### সব তথ্য একসাথে দেখতে:
```sql
SELECT * FROM public.sp_get_all_owners_details();
```

### পছন্দের কিছু কলাম আলাদা করে দেখতে:
```sql
SELECT
    owner_id,
    full_name,
    email,
    phone,
    address,
    shop_count,
    max_shop_count,
    account_status,
    shop_details
FROM public.sp_get_all_owners_details();
```

---

## ইনপুট (Inputs)
* **কোনো ইনপুট দিতে হবে না (`None`)**
* ফাংশনটি চালানো মাত্রই ডেটাবেস থেকে সব ওনারের তালিকা নিজে থেকেই রিটার্ন করে দেবে।
* **নিরাপত্তা কথা:** ব্যাকএন্ড (FastAPI) কোড দিয়ে চেক করে নিতে হবে যেন শুধু আসল অ্যাডমিনই এই ডেটা দেখতে পারে।

---

## আউটপুট কলামের তালিকা (Outputs)

| কলামের নাম | ডেটা টাইপ | সহজ বিবরণ |
| :--- | :--- | :--- |
| `owner_id` | `INTEGER` | Owner-এর নিজস্ব আইডি নম্বর |
| `full_name` | `VARCHAR` | Owner-এর পুরো নাম |
| `profile_image` | `VARCHAR` | প্রোফাইল ছবির লিংক |
| `email` | `VARCHAR` | ইমেইল ঠিকানা |
| `phone` | `VARCHAR` | ফোন নম্বর |
| `address` | `TEXT` | Owner-এর বর্তমান ঠিকানা |
| `shop_count` | `BIGINT` | এই ওনারের মোট কয়টি দোকান খোলা আছে |
| `max_shop_count` | `INTEGER` | এই ওনার সর্বোচ্চ কয়টি দোকান বানাতে পারবে |
| `account_status` | `BOOLEAN` | অ্যাকাউন্ট চালু (`TRUE`) না বন্ধ (`FALSE`) |

| `shop_details` | `TEXT` | সব দোকানের নাম (কমা দিয়ে দিয়ে লেখা) |

## ভেতরের জরুরি কিছু বিষয়
1. **`COUNT(s.shopid)`:** ওনারের মোট কয়টি দোকান আছে তা গুণে বের করে।
2. **`STRING_AGG(...)`:** একই ওনারের একাধিক দোকান থাকলে নামগুলোকে কমা (`,`) দিয়ে একটি লাইনে জুড়ে দেয়।
3. **`COALESCE(..., '')`:** ওনারের যদি কোনো দোকান না থাকে, তবে `NULL` না দেখিয়ে ফাঁকা লেখা দেখাবে।
4. **`ORDER BY o.ownerid DESC`:** একদম নতুন যুক্ত হওয়া ওনারদের তালিকার ওপরে দেখাবে।

## সম্ভাব্য বিশেষ পরিস্থিতি (Edge Cases)

| পরিস্থিতি | ফাংশনটি কী করবে? |
| :--- | :--- |
| Owner-এর কোনো দোকান নেই | `shop_count = 0` এবং `shop_details = ''` আসবে। |
| একাধিক দোকান থাকলে | সব দোকান সঠিকভাবে গণনা হবে এবং কমা দিয়ে একসাথে নাম আসবে। |
| একাউন্ট বন্ধ (Inactive) | Owner আসবে, তবে `account_status = FALSE` থাকবে। |
| ফোন বা ছবি বা ঠিকানা না থাকলে | সেই ফিল্ডগুলো স্বাভাবিকভাবে `NULL` আসবে। |
| কোনো Owner রেকর্ড না থাকলে | খালি টেবিল (Empty Result Set) রিটার্ন করবে। |

# 2. `fn_refresh_dashboard_stats()`

## সহজ কথায় এর কাজ কী?
যখনই ডেটাবেসে কোনো নতুন ইউজার বা ওনার যুক্ত হবে, ডিলিট হবে বা স্ট্যাটাস অন/অফ হবে—তখনই এই ফাংশন স্বয়ংক্রিয়ভাবে (অটোমেটিক) ড্যাশবোর্ডের মোট **9টি হিসাব** নতুন করে গুণে `DashboardStats` টেবিলে আপডেট করে দেবে।

---

## ফাংশন প্রোফাইল

| সেকশন | বিবরণ |
| :--- | :--- |
| **ফাংশন নাম** | `fn_refresh_dashboard_stats()` |
| **ধরন** | Trigger Function |
| **রিটার্ন টাইপ** | `TRIGGER` |
| **ল্যাঙ্গুয়েজ** | `PL/pgSQL` |
| **টার্গেট টেবিল** | `public.DashboardStats` (row `statsid = 1`) |
| **কাজ** | ইউজার, ওনার ও শপ সংক্রান্ত 9টি স্ট্যাটাস রিফ্রেশ করা |

---

## 9টি হিসাব যেভাবে বের হয়

| হিসাবের নাম | কীভাবে গোনা হয় |
| :--- | :--- |
| **1. Total Users** | ডেটাবেসের মোট সব ইউজারের সংখ্যা |
| **2. Total Owners** | মোট সব দোকান মালিকের সংখ্যা |
| **3. Total Shops** | সব দোকানের মোট সংখ্যা |
| **4. Active Users** | যেসব ইউজার বর্তমানে চালু আছে (`status = TRUE`) |
| **5. Inactive Users** | যেসব ইউজার বন্ধ আছে (`status = FALSE`) |
| **6. Active Owners** | যেসব ওনার সক্রিয় আছে (`roleid = 2` এবং `status = TRUE`) |
| **7. Inactive Owners** | যেসব ওনার বন্ধ আছে (`roleid = 2` এবং `status = FALSE`) |
| **8. Active Shops** | যেসব দোকান খোলা আছে (`isactive = TRUE`) |
| **9. Inactive Shops** | যেসব দোকান বন্ধ আছে (`isactive = FALSE`) |

---

## ট্রিগার সেট করার কোড (Trigger Code)
এই ফাংশন নিজে একা কাজ শুরু করতে পারে না। টেবিলগুলোর সাথে নিচের 3টি ট্রিগার লাগিয়ে দিলে প্রতি পরিবর্তনের পর ফাংশনটি নিজে থেকেই চলবে:

```sql
-- 1. Users টেবিলের ট্রিগার
CREATE TRIGGER trg_users_dashboard_stats
AFTER INSERT OR DELETE OR UPDATE OF status, roleid, ownerid
ON public.users
FOR EACH STATEMENT
EXECUTE FUNCTION public.fn_refresh_dashboard_stats();

-- 2. Owners টেবিলের ট্রিগার
CREATE TRIGGER trg_owners_dashboard_stats
AFTER INSERT OR DELETE
ON public.owners
FOR EACH STATEMENT
EXECUTE FUNCTION public.fn_refresh_dashboard_stats();

-- 3. Shops টেবিলের ট্রিগার
CREATE TRIGGER trg_shops_dashboard_stats
AFTER INSERT OR DELETE OR UPDATE OF isactive
ON public.shops
FOR EACH STATEMENT
EXECUTE FUNCTION public.fn_refresh_dashboard_stats();
```

---

## ফাংশন কল করার নিয়ম
* **হাতে কল করতে হবে না (`No Direct Call`)**
* যখনই টেবিলে নতুন ডেটা ইনসার্ট বা পরিবর্তন হবে, ট্রিগার স্বয়ংক্রিয়ভাবে এই ফাংশনটি চালিয়ে ড্যাশবোর্ডের হিসাব নিখুঁত করে দেবে।

## কাজের প্রবাহ (Execution Flow)

```text
Admin বা API অ্যাকশন (যেমন: sp_add_owner কল হলো)
                    │
                    ▼
       Owners / Users টেবিলে INSERT হলো
                    │
                    ▼
     PostgreSQL ট্রিগার স্বয়ংক্রিয়ভাবে ফায়ার হলো
                    │
                    ▼
      fn_refresh_dashboard_stats() চালু হলো
       (9টি স্ট্যাটিস্টিক পুনরায় হিসাব করলো)
                    │
                    ▼
DashboardStats টেবিলে statsid = 1 এর রো-টি আপডেট হলো
                    │
                    ▼
  Admin Dashboard API ইনস্ট্যান্ট ফ্রেশ ডেটা পেল!
```

## লক্ষণীয় জরুরি বিষয় (Important Notes)
1. **অটো-রোলব্যাক (Atomic):** কোনো প্রসিডিউরে সমস্যা হয়ে ট্রানজ্যাকশন রোলব্যাক হলে ড্যাশবোর্ডের আপডেটও আগের অবস্থায় ফিরে যাবে।
2. **একাধিকবার চলা:** `sp_add_owner` প্রসিডিউরে প্রথমে `owners` এবং পরে `users` টেবিলে ডেটা ঢোকে। তাই ট্রিগার ফাংশনটি 2 বার চলতে পারে—এটি সম্পূর্ণ স্বাভাবিক ও নিরাপদ।
3. **NOT NULL বাধ্যবাধকতা:** `status` বা `isactive` কলামে অবশ্যই `NOT NULL` রাখা উচিত; অন্যথায় `NULL` ভ্যালুগুলো অ্যাক্টিভ বা ইনঅ্যাক্টিভ কোনো হিসেবেই গণনা হবে না।
